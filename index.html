HackIndia Spark-9 2026 entry

Q-Guardian OS

An AI security operations console. A Java ingester streams packet telemetry into a FastAPI hub, a gradient-boosted detector trained on UNSW-NB15 scores every flow, and an LLM planner decides which widgets the analyst needs next. The React canvas rebuilds itself around the threat, and analysts can block a node straight from the graph.

Open live demo Read the code Watch the live demo (GIF)
Backend
FastAPI, WebSockets, Python 3.12
Detection
Gradient boosting on UNSW-NB15 flows, plus an NSL-KDD model and SMB rule for the Java ingester
Agent
gpt-oss-120b on Groq, Pydantic-validated tool calls, Qdrant case memory
Frontend
React, TypeScript, Zustand, Tailwind
Ships as
Render backend, GitHub Pages UI, Docker Compose, CI
How it's built
  1. IngestJava 17 parser turns packet records into JSON and POSTs batches
  2. DetectGradient-boosted trees score each flow; a case opens after 3 detections from one source
  3. RouteFastAPI WebSocket hub streams alerts and operator actions both ways
  4. PlanLLM planner pulls the visitor’s past cases from Qdrant memory
  5. RenderReact canvas mounts the widgets the planner asks for

Design choices

  • Parsing is one charAt pass that keeps field offsets instead of substrings, with no regex or split().
  • The planner emits JSON layout commands, and a component registry renders them, so the model never writes UI code.
  • Each visitor gets a private session: their own simulated attack, workspace and saved cases, with per-visitor and global rate limits on the shared LLM.
  • The planner returns every widget a request needs in one validated tool call, so “traffic and topology” gets both views.
  • Both detectors run on NumPy alone (the gradient-boosted trees are exported to JSON and checked against scikit-learn); a fallback to the scripted planner is shown in the UI, never silent.

Results

  • Live detector: AUC 0.94 on 82k held-out UNSW-NB15 flows, 98% precision at the alert threshold; the demo replays held-out flows it never trained on.
  • Ingester parses about 4M records/s on one core.
  • The live demo runs on the deployed backend; detections carry their closest MITRE ATT&CK technique where one fits.
  • Planner eval with gpt-oss-120b: 12/12 on a held-out set it was never tuned on and 19–20/20 on the main set (keyword baseline: 6/12 and 16/20).
  • The first detector, trained on NSL-KDD, didn’t transfer to modern traffic (AUC 0.30 on UNSW-NB15). The README documents that finding and the switch.
  • Built for HackIndia Spark-9 2026, Track 04: stateful AI agents with a dynamic UI.
  • Covers a full incident loop: alert, triage, containment, false-positive replan, and a generated incident report.
  1. 02

    Q-Guardian · 2025 research model

    HackIndia 2025 · National winner, AI Track

    The system that won the HackIndia 2025 AI Track and became my IEEE paper: behaviour-aware intrusion detection that combines Isolation Forest denoising, a Random Forest and a variational quantum circuit, then explains each detection with MITRE ATT&CK.

    Python · Flask · PyTorch · Scikit-learn · PennyLane

    How it's built
    1. IngestService 1 collects request and behaviour streams
    2. DenoiseIsolation Forest strips outliers from the training signal
    3. ClassifyRandom Forest and a variational quantum circuit (PennyLane) score each event
    4. ExplainDetections are mapped to MITRE ATT&CK techniques
    5. AlertService 3 raises alerts on a dashboard behind bcrypt auth

    Design choices

    • Ingestion, stream processing and alerting are 3 independent services, so each one scales and fails on its own.
    • A hybrid classical and quantum model targets zero-day and subtle behaviour changes that signature-based IDSs miss.
    • MITRE ATT&CK mapping turns a raw anomaly score into a named technique an analyst can act on.

    Results

    • 86% accuracy flagging anomalous traffic on live request streams.
    • Published at IEEE AIDML 2026 (first author).
    IEEE paper Walkthrough on request
  2. 03

    Deepfake Detection System

    Detects facial manipulation in video with a ResNeXt CNN, reaching 87% accuracy on 150+ test videos, and returns results through a React interface.

    Python · PyTorch (ResNeXt) · OpenCV · React

    How it's built
    1. UploadA video comes in through the React interface
    2. Skip to contact
    3. PreprocessFrames are sampled and prepared with OpenCV
    4. InferA ResNeXt CNN in PyTorch scores frames in batches
    5. ReportThe verdict returns to the React interface

    Design choices

    • Preprocessing and inference were optimised together, and frames go through the model in batches instead of one at a time.
    • The model runs behind a React interface, so anyone can test a video without touching Python.

    Results

    • 87% accuracy on 150+ test videos.
    • Per-video processing time cut from 13s to 6s.
